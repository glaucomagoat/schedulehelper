Schedule Helper

Transfer & Import Guide
For the incoming owner · Doctor and Technician scheduling
Follow these steps in order.

What you have been given

Three things arrive with this handover. You need all three.

This is one website with two halves, sharing a single set of data. The main address is the doctor scheduler. Adding /techs.html opens the technician scheduler. One backup file covers both — you import once, on the doctor side, and both halves come back together.
ItemWhat it is
A backup file
schedule-helper-backup-….json		 Every schedule, rule, setting, and user account from the old site — including passwords, so staff keep the logins they already have.
The code A Git repository you deploy to your own Netlify account.
A list of settings Roughly ten environment variables. The site will not run without them.
Treat the backup file like a password database. It contains password hashes for every account and staff time-off notes that may include personal or medical detail. Do not email it, post it in chat, or leave it in a shared folder. Transfer it the way you would transfer a password, and delete your copy once the migration is verified.

Before you start

  • A Netlify account (the free tier is sufficient)
  • Access to the Git repository
  • An Anthropic API key, if you want AI schedule generation — this is your own billing
  • A decision about the Telegram bot (see Step 5 — decide this before you begin)
  • About an hour, plus time for staff to re-link Telegram if you change bots
1Deploy the site

Create a new site in Netlify from the repository. Build settings are already in netlify.toml — you should not need to change them.

When the first deploy finishes, open the site. You will see a login page. You cannot log in yet; that is expected.

2Add the settings

In Netlify, go to Site configuration → Environment variables and add each of these. Mark the ones noted as secret.

NameWhat it doesSecret
SESSION_SECRETKeeps people logged in. Use a long random valueYes
LINK_SECRETSigns the schedule links inside notificationsYes
INTERNAL_SECRETLets the scheduler talk to itselfYes
TELEGRAM_BOT_TOKENYour Telegram botYes
TELEGRAM_BOT_USERNAMEThe bot's @nameNo
TELEGRAM_WEBHOOK_SECRETVerifies messages really come from TelegramYes
PUBLIC_BASE_URLYour site address, no trailing slashNo
TECH_ADMIN_USERNAMEThe main admin username — see the box belowNo
ANTHROPIC_API_KEYAI schedule generationYes
CVE_USER / CVE_PASSCreates your first admin loginYes
Set CVE_USER and TECH_ADMIN_USERNAME to the same name — the old site's admin username, almost certainly cve. Ignore the word "TECH" in that second name; it is misleading. It controls the doctor schedule as much as the technician one. If the two names differ, the site will look completely normal while every Telegram notification is built from the wrong place — staff receive assignments that do not match the board, or nothing at all, and nothing on screen indicates a problem. This is the single easiest way to break the handover.

Trigger a fresh deploy so the new settings take effect.

3Sign in

Open the site and log in with the CVE_USER and CVE_PASS you just set. You will land in an empty scheduler — no doctors, no locations, no schedules. That is correct. The data arrives in the next step.

4Import the data

Go to the Managers tab, find the Backup & Transfer card, and choose Import from file. Select the backup file.

Nothing is written yet. A summary appears first, showing exactly what will change — how many schedules, accounts, and logins, and which are new versus overwritten. Read it before continuing.

Choose a mode

  • Merge — adds and overwrites, leaves anything else alone. Use this. On a fresh site the result is identical to Replace.
  • Replace — deletes existing data first. Only for a deliberate do-over, and it makes you type the admin name to confirm.

Confirm, wait for the report, then reload the page when prompted. Your schedules, doctors, technicians, locations, and rules should all be present.

Everyone keeps their existing password. Passwords travel in the backup as secure hashes, so staff sign in exactly as before. You do not need to reset anything or tell anyone a new password.
5Reconnect Telegram

This is the only part that cannot be copied cleanly, so decide deliberately.

OptionWhat happens
Keep the same bot
(reuse the old token)		 Notifications keep working immediately. Nobody re-links. But the previous owner still owns the bot and could revoke access.
Create your own bot
(new token from BotFather)		 A clean break — but every doctor, technician, and administrator must tap a new invite link before they receive anything. Notifications are dark until they do.

Doctors and technicians link separately. Doctors use the Notifications tab on the doctor site; technicians and administrators use the Notifications tab on the technician site. Each tab lists who is still unlinked — work both lists, or one group is left out.

Either way, tell Telegram where your site now lives. Replace the two bracketed values and open this address once in a browser:

https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setWebhook?url=<YOUR_SITE_URL>/.netlify/functions/telegram-webhook&secret_token=<YOUR_WEBHOOK_SECRET>

A response containing "ok":true means it worked.

If you created a new bot, plan for a re-link day. Each person opens their own invite link from the Notifications tab once. Until they do, that person receives nothing — and the system cannot tell you they missed it any more clearly than showing them as unlinked. Send the invites in one batch and chase the stragglers.
6Verify before you rely on it

Work through every line. The failures that matter are the quiet ones.

Doctor side — the main address, /

  • You can sign in as the admin
  • Past months show doctor assignments, and Plans A/B/C are all present
  • A month you had marked Final still shows as Final
  • Doctors, Locations, Rules, Vacation, Medical Leave and Holidays are populated
  • A doctor portal user signs in with their existing password
  • Export a month PDF — try both Classic and New Style
  • The Notifications tab lists every doctor and shows who is linked to Telegram

Technician side — /techs.html

  • Technicians, Sites, Staffing Targets and Rules are populated
  • The month view shows published plans
  • A technician portal user signs in with their existing password
  • Export the month PDF

Both

  • Send /today to the bot and confirm the reply matches the board
  • Send yourself a test notification from each Notifications tab
  • Generate a schedule on each side to confirm the AI key works
  • Export from the new site and compare it to the file you imported
The account checks are the important ones. Schedules are easy to see at a glance; a missing login is not. Test a real portal account of each kind rather than assuming they came across.

If something looks wrong

SymptomCause and fix
Login page returns a server error SESSION_SECRET is missing. Add it and redeploy.
Schedules imported but nobody can log in The admin username does not match the old site's. Re-check CVE_USER and TECH_ADMIN_USERNAME, then import again.
Site is empty after importing The import report will say what was skipped. Reload the page first — the app caches data until it reloads.
Bot does not answer The webhook still points at the old site. Re-run the Step 5 address.
Nobody receives notifications If you changed bots, everyone must re-link. Check the Notifications tab for who is still unlinked.
Links in messages give a 403 LINK_SECRET differs from the old site. Either restore the old value or send a fresh notification, which generates new links.

Keep taking backups

The same Export all data button is your ongoing backup. There is no other recovery path — the data lives only in this site's storage. Export on a schedule you are comfortable with, and always before a bulk change such as clearing or regenerating a plan.

A backup you have never restored is a guess. Once a year, import one into a throwaway site and confirm it comes back.
